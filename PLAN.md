# PLAN — единый план доработок DensitoAI (один файл, обновляется по ходу)

Порядок: от простого к сложному, по одному шагу, каждый шаг заканчивается проверкой и коммитом.
Статусы: ☐ не начато · ◐ в работе · ☑ сделано. Подробности и обоснование — `docs/IMPROVEMENT_ANALYSIS.md`.

## 0. Данные (фон, идёт параллельно)

Открытых DXA-снимков с разметкой качества укладки в свободном доступе **нет** — проверено
(Mendeley, Zenodo, Kaggle, Hugging Face, PhysioNet, Figshare, каталоги bone.technology / AMID / Awesome-Medical-Dataset).
Что есть:

| Набор | Что это | Объём | Доступ | Статус | Для чего нам |
|---|---|---|---|---|---|
| **BUU-LSPINE 400** | рентген поясничного отдела AP + LA, разметка верх/низ краёв L1–L5 линиями | 800 изображений (400 AP) | свободно (Google Drive) | ☑ скачан, `external_datasets/BUU-LSPINE/` | эталон оси и позвонков → предобучение детектора оси/позвонков, проверка признака `axis_angle` |
| **MTDDH** | рентген таза AP, разметка качества укладки (ротация/симметрия) + keypoints | 1250 изображений | CC BY 4.0 | ☑ скачан, `external_datasets/MTDDH/` | предобучение признаков симметрии/ротации таза для `hip_pos` |
| **FracAtlas** | рентген, в т.ч. бедро; метка `hardware` (металл) | 338 снимков бедра из 4083 | CC BY 4.0 | ☑ скачан | детектор инородных предметов, контур бедра |
| **DEXSIT / DEXSIT-v2** (Sethu Institute, Индия) | **настоящие DXA** AP: позвоночник, левое и правое бедро | 441 (+200) PNG | по EULA: подписать от организации с рабочего e-mail и отправить `tamilselvi@sethu.ac.in` | ☐ нужен запрос от владельца команды | тест на другом аппарате, OOD-детектор, доменное предобучение контура B |
| **Arak Bone Densitometry** (Иран) | **настоящие DXA** PNG: L1–L4, шейка бедра, бедро целиком, предплечье; метки норма/остеопения/остеопороз | 4020 PNG | Google Drive, требуется запрос доступа (кнопка «Запросить доступ» в папке) | ☐ нужен запрос от владельца | то же, самый большой реальный DXA-набор |
| BUU-LSPINE 3600 | расширенный набор | 7200 | Google-форма → одобрение → письмо | ☐ опционально | больше эталонов оси |
| UK Biobank DXA | ~100 000 участников | — | заявка, недели/месяцы, платно | ✗ не успеть | — |

Честно: ни один внешний набор не содержит разметки «укладка/ось/предметы/ROI» для DXA, поэтому
они не поднимут метрики редких классов напрямую. Они дают (а) эталон анатомии для более точных
признаков, (б) доказательство устойчивости на чужом домене, (в) предобучение. Для редких классов
основной путь — физически обоснованная синтетика на своих снимках (шаг 4) и разметка рентгенолога.

## Шаги

| № | Шаг | Что делаем | Проверка готовности | Статус |
|---|---|---|---|---|
| 1 | Быстрые правки удобства | веб: XLSX, сортировка по риску, фильтры, группировка по исследованию, прогресс, понятные ошибки, экранирование; XLSX: лист «Сводка», автофильтр, подсветка; единый benchmark скорости в README | ручная проверка в браузере, скриншоты | ☐ |
| 2 | Надёжность API + стресс-тест | безопасная распаковка zip (Zip Slip, лимиты), каталог на запрос, имена по SOP UID, `/api/results` только своего запроса; набор искажений (теги, MONOCHROME1, 16-bit, шум, яркость, resize, битые/вложенные zip, одинаковые имена) → `docs/ROBUSTNESS_REPORT.md` с flip-rate / Failure-rate / p95 | отчёт + pytest зелёный + два параллельных zip с одинаковыми именами не смешиваются | ☐ |
| 3 | Честный риск и зона «не уверен» | cross-fit калибровка по исследованиям, conformal-зона отказа, Brier/ECE/reliability, risk–coverage; в CSV-debug и UI: низкий/средний/высокий риск, «требует врача»; переименовать формулировки (§7 анализа) | reliability diagram в METRICS_REPORT, OOF-метрики не ухудшились | ☐ |
| 4 | Данные для редких классов | синтетика на своих снимках (поворот оси, сдвиг, вставка плотных объектов, обрезка поля бедра) с контролем реалистичности; детектор оси/позвонков, предобученный на BUU-LSPINE, как новый признак; проверка только по OOF | OOF F1/AUC по sp_pos, sp_axis, hip_pos с ДИ до/после | ☐ |
| 5 | Карточка решения и цикл врача | по критерию: измерение, норма, скор/порог, причина, действие; очередь по риску; «согласен / исправить / не уверен»; JSONL-журнал; экспорт для дообучения; скрипт дообучения на подтверждениях | демо-сценарий проходит от загрузки до экспорта | ☐ |
| 6 | Режим лаборанта и панель отделения | экран «переснять сейчас»; отчёт по партии: доля пересъёмок, типы, тренд по аппарату/дате (теги DICOM), HTML + XLSX | отчёт на 499 файлах | ☐ |
| 7 | OOD-детектор чужого аппарата | fingerprint тегов + расстояние в эмбеддингах; тест на DEXSIT/Arak (если получим) и на рентгенах | внешние снимки помечаются «оценка ненадёжна» | ☐ |
| 8 | Nested CV и model card | вложенная group-CV, импутация внутри фолда, честные цифры рядом с текущими | таблица в METRICS_REPORT | ☐ |
| 9 | Внедрение | watch-folder / DICOM C-STORE, SR через валидатор и Orthanc | round-trip в Orthanc | ☐ |
| 10 | Финал | ТЗ рентгенологу (уже написано, `docs/RADIOLOGIST_TEST_BRIEF.md`), правки по его заключению, ФИО и контакты, презентация | — | ☐ |

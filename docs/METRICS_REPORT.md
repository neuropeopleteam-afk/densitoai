# Отчёт по метрикам (формат ТЗ §8.4)

Все метрики получены на **out-of-fold (OOF) предсказаниях** repeated GroupKFold (5×5,
группировка по `study_uid`, чтобы снимки одного исследования не попадали одновременно
в train и validation). Доверительные интервалы — study-level bootstrap, 95%, 1000
повторов. Источник: `models/metrics_summary.json` (сгенерирован пайплайном обучения,
раздел README §11).

**Как читать эту таблицу:** `n_pos` — число позитивных (нарушение присутствует) примеров
в валидации. Когда `n_pos < 10`, ДИ по построению широкий и малоинформативный — это
статистическое свойство малых выборок, не брак модели. Такие строки помечены явно.

## 1. Позвоночник (Поясничный отдел позвоночника)

| Критерий | n_valid | n_pos | ROC-AUC (stacked) | F1 (OOF) | F1 95% ДИ | Порог | Метод порога |
|---|---|---|---|---|---|---|---|
| sp_pos (положение) | 166 | 10 | 0.596 | 0.381 | [0.000; 0.710] | 0.813 | prevalence |
| sp_axis (ось/сколиоз) | 166 | 17 | 0.738 | 0.381 | [0.096; 0.596] | 0.756 | f1_optimal_oof |
| sp_art (посторонние предметы) | 166 | 35 | 0.823 | 0.598 | [0.329; 0.756] | 0.557 | f1_optimal_oof |

**Комментарий:** `sp_art` (детекция металла/посторонних предметов) — самый надёжный
критерий позвоночника, AUC 0.82 при 35 позитивах. `sp_pos` — статистически слабый
(AUC 0.60, близко к случайному), доверительный интервал F1 включает 0 — на этом
критерии система не гарантирует определённого качества и должна восприниматься как
предварительная эвристика, а не устоявшийся классификатор.

## 2. Бедро (Проксимальный отдел бедра), объединённая модель с зеркалированием

| Критерий | Сторона | n_valid | n_pos | ROC-AUC (stacked) | F1 (OOF) | F1 95% ДИ | Надёжность |
|---|---|---|---|---|---|---|---|
| hip_pos (положение) | оба | 329 | 79 | 0.704 | 0.511 | [0.311; 0.672] | ok |
| hip_pos | право | 161 | 39 | 0.669 | 0.419 | [0.149; 0.656] | ok |
| hip_pos | лево | 168 | 40 | 0.731 | 0.592 | [0.312; 0.772] | ok |
| hip_roi (область интереса) | оба | 329 | 16 | 0.917 | 0.636 | [0.200; 0.932] | пограничная |
| hip_roi | право | 161 | 7 | 0.970 | 0.636 | [0.000; 1.000] | **ненадёжно: <10 позитивов** |
| hip_roi | лево | 168 | 9 | 0.866 | 0.636 | [0.000; 1.000] | **ненадёжно: <10 позитивов** |

**Комментарий:** `hip_roi` показывает высокий точечный AUC (0.87–0.97), но при разбивке
по стороне число позитивов падает до 7–9, из-за чего 95% ДИ по F1 расширяется до
[0.0; 1.0] — де-факто интервал не исключает ни полный провал, ни идеальную работу на
этой подвыборке. Объединённая (не разбитая по стороне) метрика `hip_roi` статистически
более устойчива за счёт большего n (16 позитивов), и именно она используется в проде
как основной сигнал (зеркалирование левого/правого бедра в одну модель — сделано
намеренно, чтобы не делить и без того малую выборку на 4 части).

## 3. Сводная оценка по надёжности (для экспертной проверки)

| Уровень надёжности | Критерии |
|---|---|
| Надёжно (n_pos ≥ 15, AUC > 0.7) | sp_art, sp_axis, hip_pos (оба + по стороне), hip_roi (объединённая) |
| Пограничная надёжность | sp_pos (AUC ~0.6, но n_pos=10) |
| Статистически ненадёжно (n_pos < 10) | hip_roi по правой стороне (7), hip_roi по левой стороне (9) |

## 4. Ограничения методологии (полная честность)

1. Датасет обучения ограничен несколькими сотнями исследований — это определяет ширину
   всех доверительных интервалов выше, а не выбор алгоритма.
2. Пороги подобраны по OOF-F1 (`f1_optimal_oof`) там, где позитивов достаточно для
   устойчивой оптимизации; для `sp_pos` (10 позитивов) применён более консервативный
   `prevalence`-порог, чтобы не переобучить порог на единичных примерах.
3. Метрики посчитаны на тренировочных данных с честным OOF-разбиением — они не
   гарантируют то же качество на закрытом тестовом наборе организаторов, особенно для
   критериев с малым n_pos.
4. Полная методология обучения, признаков и валидации — README §8, §10, §11 и
   `docs/ENGINEERING_REPORT.md`.

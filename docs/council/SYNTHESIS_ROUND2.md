# Консилиум DensitoAI — раунд 2 (критика) и финальный приоритетный план

Дата: 19.09.2026. Участники раунда 2: Claude Fable 5, Gemini 3.1 Pro, Claude Opus 5, GPT 5.6 Sol, Kimi K3 — каждый получил синтез раунда 1 и разбирал чужие идеи на реализуемость за 1–3 дня одним разработчиком на CPU, риски на защите и стенде, что вырезать. Отчёты: `model-council-<model>-round2.md` (5 файлов).

## Главный вывод раунда 2

План раунда 1 невыполним по объёму. Claude Fable 5 оценил сумму предложений в 200–260 часов при реальном бюджете 70–90, Claude Opus 5 — в 180–220 при 60–80; оба независимо требуют вырезать половину, а не расставлять по дням. Opus добавил два системных дефекта: пять «вау»-демонстраций конкурируют за одно окно 90–120 секунд из 300 (с учётом обязательного слайда о команде по [Порядку ЛЦТ](https://i.moscow/upload/lending/lending_Ltc/ad043e.pdf)), а восемь предложенных документов нарушают правило «сначала продукт, потом бумажки» — остаются только документы, которые генерирует код, плюс не больше трёх рукописных.

## Что остаётся спорным и как решено

| Вопрос | Позиции после раунда 2 | Решение |
|---|---|---|
| Nested на слайде | Opus, Sol — на слайде (мелко / одна консервативная цифра); Fable, Kimi, Gemini — бэкап-слайд | На слайде: OOF с ДИ, полоса ориентиров заказчика, одна строка мелким шрифтом «внешняя оценка без подгонки порога: …»; полная таблица — README и бэкап-слайд. Цифру называем сами, но не заголовком |
| Пулинг двух бёдер hip_pos | Fable, Kimi, Opus — за при согласованности меток сторон ≥ 85 %; Gemini, Sol — против жёсткого пулинга (скрывает односторонний брак; конкурс оценивает строку на файл) | Признаки контекста исследования (max / mean / расхождение сторон) как дополнительные, без замены скора файла; только при согласованности ≥ 85 %; приёмка по nested paired gain; fallback на одно бедро обязателен |
| Prevalence-порог | Fable, Kimi, Opus — за; Sol — не по умолчанию, сравнить три правила внутри nested; Gemini — режим высокой чувствительности | Три предзаданных правила (текущий F1-оптимум, prevalence ×1,0, prevalence ×1,4) сравниваются внутри nested; берётся самое стабильное по outer-fold regret. В UI позитивы редких критериев с малым запасом — жёлтое «замечание», не красное «нарушение» (Opus). Режим высокой чувствительности — только UI, не CSV (Kimi) |
| Угол искривления оси и деформация оси | Gemini — обязательная маркировка и подавление оси; Fable, Sol, Opus, Kimi — не трогать официальный `violation_type` без OOF, на L1–L4 угол искривления оси плохо определён | Флаг «замечание: искривление оси столба, требует оценки врача» в `extras`, без слова «Кобб» и градусов; официальные колонки не меняются. Эксперимент Gemini (10 деформаций оси: требует ли система пересъёмки) провести и честно записать результат в EVIDENCE |
| Инпейнтинг белых линий | Fable, Kimi, Gemini — нужен против конфаундера; Sol — разрушит анатомию 3–5 px и создаст train–test shift | Сначала аудит «линии × метка» (2 ч); инпейнтинг — только если ассоциация есть и OOF после него не хуже; в production не по умолчанию |
| Вентиль: ожидаемый эффект | Fable +0,05–0,10; Kimi реалистично +0,02–0,05 и 6–8 ч из-за пересборки контракта моделей (референсные OOF в pickle); Sol — «не обещать число», selector bias | Делаем через nested с предзаданными весами {0, 0,25, 0,5, 0,75, 1}; принимаем при приросте ≥ 0,03 в ≥ 7 из 10 повторов без потери macro-F1; в документах — только измеренная nested-цифра |
| Документы | Kimi, Fable, Sol — data card, EXPERIMENTS_LOG, JSON Schema, DZM_CONFORMANCE как дешёвая зрелость; Opus — не больше трёх рукописных | Один `docs/EVIDENCE.md` (происхождение и лицензии данных, отвергнутые гипотезы, ограничения), model card генерируется из метрик, JSON Schema внутри валидатора, `DZM_CONFORMANCE.md` как таблица статусов «сделано / частично / не делаем» с рамкой «внутренняя имитация классификатора» |

## Что вырезано (согласие четырёх–пяти моделей)

1. Доразметка 200–300 внешних снимков и любое supervised-обучение на внешних PNG (снял сам Kimi K3); внешние наборы — только OOD-тест.
2. Обучающая синтетика поворотов для sp_axis и sp_pos, «black hole» аугментации, blind-test синтетики врачом; синтетика остаётся как предвычисленный фантом-тест и, при остатке времени, fold-aware вырезы предметов для sp_art и обрезка поля для hip_roi с приёмкой по OOF.
3. Подавление официального `sp_axis` по углу искривления оси; слово «деформация оси» и градусы искривления оси в выходе.
4. C-STORE, Orthanc как поток, Kafka, любые заявления о совместимости с РИС города; автоматический аудит дефектов В1–Д2 в UI.
5. Контрфактический ghost overlay, отчёт по операторам, per-case metamorphic на инференсе (metamorphic — только на эталонном пакете в `verify.sh`).
6. Детектор ориентиров U-Net с переносом с BUU-LSPINE/AASCE и любые GPU-часы на бэкбоны в первую неделю.
7. Живой прогон как основной маршрут защиты; «похожие случаи» и heatmap в карточке; интерактивный режим слепой оценки для жюри; страница на 300 снимков (слита с ревизией 40–60).
8. Отдельные DATA_CARD, EXPERIMENTS_LOG, threat model, evidence bundle — сведены в `docs/EVIDENCE.md` и `verification_report.html`.

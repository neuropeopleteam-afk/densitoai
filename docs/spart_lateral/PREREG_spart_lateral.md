# Предрегистрация: боковое ограничение зоны посторонних предметов (`sp_art`), 2.5.x

Записано 28.09.2026 в 12:05 МСК, до расчёта новых признаков и до любой метрики на метках.

## Почему

Самопроверка образа 2.5.0 (PLAN «28.09 Н4»): на образце организаторов `CR000000_ПОП.dcm` признак `band70`
(плотные участки в верхних 70 % протяжённости кости по вертикали, без бокового ограничения) насчитал 303 мм²:
в полосу попали концы рёбер в верхних углах кадра. Итог — «Присутствуют посторонние предметы», 0.952; в 2.4.x
на том же файле норма 0.325. В предрегистрации 2.5 (`PREREG_spart_position.md`) боковой фильтр сознательно не
вводился. Гипотеза анатомическая: врач оценивает предмет, который проецируется на позвонки L1–L4 или рядом с ними;
рёбра и то, что далеко сбоку от позвоночника, на измерение не влияют.

Известно до записи (и могло повлиять на выбор): на одном образце организаторов (не входит в обучающие данные);
на обучающих метках в диапазоне band70 200–400 мм² 3 кадра, все без предметов (посмотрено 28.09 11:50 при разборе
Н4, метрики признака-кандидата не считались). Образец организаторов в решение не входит, его результат только
сообщается после решения.

## Признак

Те же компоненты, что у `foreign_object_features` (фон + 3σ вне маски кости, площадь ≥ 4 пикс.), та же полоса
по вертикали `[y0, y0 + 0.7·(y1 − y0)]`. Дополнительно пиксель компоненты учитывается, только если в той же строке
есть маска кости и x пикселя лежит в `[xl(y) − m, xr(y) + m]`, где `xl(y)`, `xr(y)` — крайние пиксели маски кости
в этой строке, `m` — боковой запас в мм (шаг по x 0.6 мм). Компонента учитывается, если таких пикселей ≥ 4.
Для каждого `m`: площадь (мм²), `log1p` площади, максимальный перепад `gap` учтённых компонент, число компонент.

Сетка `m ∈ {5, 10, 20, 40}` мм задана заранее. `m = ∞` — это `band70` (поставка 2.5.0).

## Кандидаты контура A (всегда два признака)

- `base` — `[metal_metal_area_mm2, metal_metal_max_intensity_gap]` (2.4.x);
- `band70` — `[metal_metal_band70_area_log, metal_metal_band70_max_gap]` (2.5.0);
- `lat<m>` — `[lat<m>_area_log, lat<m>_max_gap]`.

## Протокол

Тот же, что у `tools/spart_position/spart_position_gate.py` (бит в бит для `base` и `band70`): внешний
GroupKFold(shuffle, random_state = 42 + r), 5 фолдов × 20 повторов, группы — компоненты связности
(исследование, хэш пикселей); внутренний GroupKFold 3 фолда; контур A — StandardScaler → LogReg(C = 1, balanced);
контур B — `imagenet`, StandardScaler → PCA(32) → LogReg(C = 0.1, balanced); стек 0.5/0.5 по рангам
относительно inner-OOF; порог — `prevalence_x1.4` на inner-OOF стека.

Ветки:
- `gate_lat` — на каждом внешнем фолде выбирается один из `{band70, lat40, lat20, lat10, lat5}` по максимуму
  AUC стека на inner-OOF; при равенстве — больший `m` (`band70` первым — ближе к поставке);
- `fixed:<кандидат>` — кандидат задан на всех фолдах.

## Правило решения (записано до запуска)

Цель — убрать анатомическую ложную тревогу, не потеряв качество, поэтому правило — «не хуже поставки 2.5.0 и
по-прежнему лучше 2.4.x». Вариант `L` = мода выбора `gate_lat` по 100 фолдам (если мода — `band70`, гипотеза
не принята). `L` внедряется, только если выполнены все пункты:

1. `gate_lat` против `band70`: средний ΔAUC стека ≥ 0, ΔAUC ≥ 0 в ≥ 14 из 20 повторов, средний Δmacro-F1 ≥ 0;
2. `fixed:L` против `band70`: то же;
3. `fixed:L` против `base`: правило проекта, которое прошёл `band70` — ΔAUC ≥ 0.03 в ≥ 14 из 20, Δmacro-F1 ≥ 0.

Дополнительно сообщаются (в решение не входят): парный гейт `tools/paired_gate.py` `fixed:L` против `band70`,
число флагов на отрицательных кадрах (ложные тревоги) по OOF, судьба трёх кадров band70 200–400 мм², совпадение
с врачами на 40 кадрах слепой проверки, образец организаторов.

Если правило не выполнено — остаётся `band70` (2.5.0 как есть), ограничение с образцом дописывается в документы.

# DensitoAI — Финальный план (после ревью Fable 5)

## Смена архитектуры (главное решение)
Отказ от «одна CNN на всё» → двухконтурная система:
- **Контур A (геометрия):** маска кости → угол оси позвоночника, детектор металла
  (посторонние предметы/эндопротез), положение ROI в мм (через PixelSpacing 1.05×0.6мм),
  кривизна центральной линии (сколиоз — НЕ штраф по оси).
- **Контур B (эмбеддинги):** замороженный EfficientNet-B0 → эмбеддинг → логрегрессия
  с L2 (не fine-tuning всей сети).
- **Стэкинг:** ранговое усреднение A+B, веса по OOF с группировкой по study.
- Бедро: зеркалить правое → единая модель на 2 критерия (не 2×2).
- Синтетические позитивы: поворот корректных spine-снимков на 4-12° для критерия «ось»
  (гарантированно верная метка); copy-paste металла для «посторонних предметов».
- Аугментации: НИКАКИХ поворотов на реальных метках (портят «ось»); только
  яркость/контраст/шум/лёгкий сдвиг.

## План действий по пунктам
1. Реализовать Контур A: сегментация кости, угол оси, детектор металла, ROI в мм.
2. Реализовать Контур B: замороженные эмбеддинги + логрегрессия per критерий.
3. Стэкинг + отдельная модель «есть нарушение» (первый этап скоринга, источник quality_prob).
4. Честная валидация: repeated GroupKFold (5×5), study-level bootstrap ДИ, пороги без
   подгонки на <10 позитивах (физические/prevalence-пороги для редких классов).
5. Переписать inference.py: обработка каждого файла отдельно, try/except с fallback-строкой,
   единый config.yaml (пороги, веса — используется и gradcam.py, и demo).
6. Выходной формат строго по официальным ответам:
   `path_to_study, study_uid, image_uid, anatomical_region, quality_class, violation_type,
   quality_prob, processing_status, time_of_processing`.
   - anatomical_region: «Поясничный отдел позвоночника» / «Проксимальный отдел бедра» (без стороны)
   - violation_type: точный список из docx, разделитель «;», пусто если нет нарушений
   - quality_prob: [0;1], из первого этапа скоринга (не noisy-OR по головам без валидации)
   - Проверить формат на образце ответа от организаторов (запросить письменно, если не выдан)
7. Валидатор входа (бонус + снижение риска падения на тесте): DICOM парсится? Регион
   определяется уверенно? Иначе — флаг «нестандартное изображение» + консервативный ответ.
8. Docker-контейнеризация с пиновкой версий + скрипт сборки/запуска Linux (блокер — делать рано).
9. README.md по чек-листу ТЗ.
10. Дешёвые бонусы (по порядку часы/балл): защита от нестандартных входов, оценка белой
    разметки денситометра, детектор эндопротеза (тот же детектор металла), сколиоз как
    сопутствующая находка, Grad-CAM с наложением измеренной оси/ROI/металла.
11. Инструкция эксперту на 1 страницу (обязательна, не бонус).
12. Презентация по шаблону — 12-15 содержательных слайдов (не заполнять все 37 заготовок).
13. Развернуть на сервере, сквозная проверка на всех 499 файлах, затем на закрытом тесте.
14. Письменно спросить организаторов: образец файла ответа, способ определения региона
    на тесте, на чём построены метки теста («Итог» или критерии), лимит времени инференса.
15. (Отложено) Задание для тестирования врачом-рентгенологом — на этот раз ключевая часть
    валидации контура A (угол/ROI пороги), не просто финальная проверка.

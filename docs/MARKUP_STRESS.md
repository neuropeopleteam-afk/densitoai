# Разметка денситометра на изображении: стресс-тест и очистка (24.09.2026)

## Откуда вопрос

Разъяснение организаторов 24.09.2026 (`docs/qa/ORGANIZERS_2026-09-24.md`): «Отдельной разметки анатомических
областей в датасете нет. На части снимков такая разметка денситометра есть прямо на изображении, но сохраняется она
не всегда, поэтому оценивать её не требуется». Значит, на закрытом тесте часть кадров может прийти с впечатанными
контурами ROI сканера, а сервис обучен на кадрах без них.

## Что в данных заказчика

- 499 DICOM: плоскостей оверлея DICOM (60xx) нет ни в одном файле.
- Детектор тонких прямых линий (`src/markup_clean.py`) на 499 кадрах: 0 кадров с разметкой. Просмотр кандидатов
  более мягкого поиска — края маски поля сканирования и импланты, не контуры ROI.

## Стресс-тест

`tools/markup_stress.py make`: копии 499 кадров с впечатанной разметкой в стиле отчёта денситометра — позвоночник:
рамка L1–L4 и три межпозвонковые линии; бедро: рамка области и повёрнутая на 45° рамка шейки; линия 1 px, яркость
250. Прогон образом (`src/inference.py`, `--network none`), сравнение с эталоном 499 (`tools/markup_stress.py compare`).

| Вариант | Смена класса | Что меняется |
|---|---|---|
| Разметка без очистки (2.4.0 до 24.09) | **146 из 499 (29,3 %)** | бедро: +74 «нарушения» (укладка, область интереса); позвоночник: −50 «посторонних предметов», −18 «оси» |
| Очистка только прямых линий | 40 (8,0 %) | остаток — повёрнутая рамка шейки бедра |
| Очистка прямых и наклонных линий (в сервисе) | **21 из 499 (4,2 %)** | бедро 8, позвоночник 13; изменения в обе стороны |

Для сравнения — устойчивость к другим возмущениям входа на 81 кадре (`docs/DZM_CONFORMANCE.md`): 27,2 / 18,5 / 17,3 %.

## Как работает очистка

`src/markup_clean.py`, вызывается в `normalize_pixels_ex` сразу после окна 1–99 % — одинаково для пакетного пути,
API и DICOM-приёмника.

1. Детектор: тонкая (1–2 px) горизонтальная или вертикальная линия почти постоянной яркости, ярче соседей с обеих
   сторон больше чем на 40 уровней, длиной не меньше 25 px.
2. Включение: только если таких отрезков не меньше 4. На 499 кадрах заказчика — 0 срабатываний, на синтетической
   разметке — 499 из 499; на внешних наборах с реальной разметкой сканера: DEXA-Osteo 199 из 344, Arak 80 из 500,
   Chinese Hip (рентген без разметки) 0 из 60.
3. Закраска: пиксели прямых линий — средним ближайших незатронутых соседей поперёк линии; после этого наклонные
   тонкие отрезки (белый top-hat 5×5 → HoughLinesP) — `cv2.inpaint` без расширения маски.

## Почему числа поставки не меняются

Очистка не срабатывает ни на одном из 499 кадров, поэтому признаки, эмбеддинги, OOF-оценки, пороги и метрики
идентичны. Проверено регрессией: образ с очисткой на 499 файлах — 0 различий с эталоном этого сервера
(`densito_private/regress499/regress_2_4_0_msk.csv`). Модели не переобучались.

## Ограничения

- Разметка синтетическая: геометрия приближена к отчёту денситометра, а не скопирована с конкретной версии ПО.
  Реальная разметка может быть другой яркости, толщины или цвета (цветные линии в RGB-кадре после перевода в
  оттенки серого могут оказаться темнее кости и не пройти порог контраста).
- Остаток 4,2 % — места, где линия шла по кости и закраска по соседям неточна.
- Текстовые подписи сканера (цифры BMD, названия позвонков) детектор не ищет.

## Воспроизведение

```bash
python tools/markup_stress.py make --src <499 DICOM> --dst /tmp/markup/in
docker run --rm --network none -v /tmp/markup/in:/ds/Исследования:ro -v /tmp/markup/out:/out --entrypoint python \
    densitoai:2.4.0 src/inference.py --input /ds/Исследования --output /out/results.csv --debug-csv auto --path-mode relative
python tools/markup_stress.py compare --base regress_2_4_0_msk.csv --cand /tmp/markup/out/results.csv
python tests/test_markup_clean.py
```

# Калибровка вероятностей: что означают `quality_prob` и скоры критериев (2.5.0, 27.09.2026)

Отчёт отвечает на один вопрос: можно ли читать числа, которые выдаёт сервис, как вероятности, или только
как ранги. Числа поставки (модели, пороги, `config.yaml`, 9 колонок CSV) этот отчёт не меняет; решение
`calibration.apply_to_quality_prob: false` остаётся в силе. Все значения — на OOF-предсказаниях того же разбиения,
что и `docs/METRICS_REPORT.md`; скрипт `tools/calibration_report.py`, полный JSON — `docs/calibration/calibration.json`,
диаграммы — `docs/calibration/reliability_*.svg` (только агрегаты, без кадров). Тест — `tests/test_calibration_report.py`.

В 2.5.0 изменился только критерий `sp_art` (признак предметов в зоне измерения, `docs/NESTED_GATE_REPORT.md`, часть 8),
поэтому пересчитаны строки позвоночника и `sp_art`; строки бедра и остальных критериев совпадают с 2.4.0.
Команда: `OMP_NUM_THREADS=1 python tools/calibration_report.py`.

## Что именно оценивается

- **`quality_prob` (области).** В `src/inference.py` это смесь `0.5 * any-модель + 0.5 * max скоров критериев`
  (`stacking.any_blend_weight_model`, `any_violation_aggregation: max`), затем согласование с классом
  (`consistent_quality_prob`): при `quality_class = 1` значение сжимается в [0.5; 1], при 0 — в [0; 0.5). На OOF оно
  воспроизводится как в `src/eval_oof_metrics.py` (OOF any-модели — StratifiedGroupKFold(5), 3 сида; ROC-AUC итогового
  quality_prob 0.846 / 0.760 совпадает с `models/metrics_oof_full.json`). Вариант «до согласования» показан отдельно.
- **Скоры критериев** (`sp_pos`, `sp_axis`, `sp_art`, `hip_pos`, `hip_roi`) из `models/oof_stacked_<region>_<crit>.csv`:
  `score` — стэкнутый ранговый скор (0.5 · ранг контура A + 0.5 · ранг контура B), с ним сравнивается порог;
  `p_cal` — Platt из `models/calibration.pkl` (выводится как `<crit>_p_cal` в debug-CSV и `p_cal` в API details),
  параметры подобраны на всём OOF, поэтому оценка на том же OOF **оптимистична**; `p_cal_crossfit` — тот же Platt,
  но обученный на чужих фолдах (GroupKFold(5) по исследованиям со стратификацией по положительным исследованиям,
  зерно 0) — честная оценка того, чего ждать на новых данных.
- **Метрики.** Диаграмма надёжности в двух разбивках: 10 бинов равной ширины (ECE10, MCE10) и 5 квантильных (ECE q5).
  Brier и лог-лосс, рядом Brier константного предиктора (доля позитивов). Наклон и сдвиг логистической рекалибровки
  `y ~ a + b·logit(p)` (идеал b = 1, a = 0; b < 1 — предиктор слишком уверен, b > 1 — слишком осторожен). 95 % ДИ
  для ECE10 и Brier — percentile-бутстрап по исследованиям, 500 повторов, зерно 0. Доля строк в зоне «не уверен» —
  `|score − threshold| <= margin`, запасы из `config.yaml: uncertainty.margin_by_criterion`.

## Выводы

1. **`quality_prob` — грубая вероятность, не точная.** ECE10 0.14 (позвоночник) и 0.15 (бедро), Brier 0.166 / 0.198
   против константы 0.231 / 0.201: для бедра выигрыш над «всегда доля позитивов» почти нулевой (skill 0.02), для
   позвоночника — 0.28 (в 2.4.0 — 0.14). Наклон 0.91 / 0.58 и сдвиг −0.87 / −0.85: значения в зоне класса 1 систематически завышены.
2. Как читать: `quality_prob >= 0.5` означает «сервис поставил класс 1», а не «шанс нарушения больше половины».
   На OOF при 0.5–0.8 нарушение подтверждается у 44 % кадров позвоночника, при >= 0.8 — у 75 %; для бедра при
   0.5–0.9 — у 36 %, при >= 0.9 — у 96 %. Ниже 0.5 нарушение остаётся у 12 % (позвоночник) и 19 % (бедро) кадров (пропуски).
3. Внутри класса `quality_prob` — ранг: порядок кадров по нему осмыслен (ROC-AUC 0.846 / 0.760), разница «0.72 против
   0.78» — нет. Для сортировки очереди на просмотр он годится, для формулировок вида «вероятность нарушения 78 %» — нет.
4. Шаг согласования с классом улучшает не только ROC-AUC, но и калибровку: ECE10 0.215 → 0.137 (позвоночник),
   0.225 → 0.153 (бедро); Brier 0.197 → 0.166 и 0.211 → 0.198. Смесь до согласования сжата к 0.4–0.8 (наклон 1.83 у
   позвоночника — слишком осторожна), согласование её растягивает.
5. **Ранговые скоры критериев вероятностями не являются** — и по построению (ранги распределены равномерно), и
   по числам: ECE10 0.26–0.45, Brier 0.19–0.29 хуже константы (0.05–0.18) у всех пяти. Читать их можно только как
   ранг и как расстояние до порога; сравнивать между критериями нельзя.
6. `p_cal` (Platt, `calibration.pkl`) — единственная величина по критериям, которую можно читать как вероятность,
   и только приблизительно. Cross-fit: Brier ниже константы у всех пяти (0.042 против 0.057; 0.073 против 0.092;
   0.106 против 0.166; 0.167 против 0.182; 0.041 против 0.046), ECE10 0.01–0.10.
7. Для `sp_art` и `hip_pos` (17 и 24 положительных исследования) cross-fit Platt близок к калиброванному: наклон 0.91
   и 0.77, ECE q5 0.03–0.04; `p_cal` здесь можно читать как вероятность с точностью около ±0.1.
8. Для `sp_pos`, `hip_roi`, `sp_axis` (6, 6 и 10 положительных исследований) наклон cross-fit 0.14, 0.41, 0.54:
   p_cal слишком уверен на хвостах, а параметры Platt между фолдами меняются до 3–5 раз (a от 8 до 45). Здесь `p_cal`
   годится только как «низкая / средняя / высокая», числу после запятой доверять нельзя.
9. Порог по правилу prevalence стоит там, где калиброванная вероятность нарушения по критерию 0.22–0.34
   (`p_cal_at_threshold`). То есть флаг критерия означает «шанс нарушения от пятой части–трети и выше»: правило порога
   намеренно смещено в сторону чувствительности, и это надо помнить при чтении `violation_type`.
10. Зона «не уверен» помечает 13.9 % строк позвоночника (в 2.4.0 — 14.5 %) и 9.4 % строк бедра (строка в зоне, если спорный хотя бы один
    критерий области); 3.6–6.0 % — доля строк в зоне по каждому критерию отдельно (уточнено в 2.4.1). В зону попадает 71 % ошибок
    `sp_pos` (10 из 14), 41 % ошибок `hip_roi` (7 из 17) и 21 % ошибок `sp_art` (6 из 28), но 0 % ошибок `sp_axis` (0 из 17) — зона по запасу отлавливает ошибки только там, где
    они группируются у порога.
11. **Ограничения при 6–17 положительных исследованиях.** ДИ ECE10 шириной 0.07–0.15, Brier — до ±0.06;
    бутстрап-ДИ ECE смещён вверх (ECE — положительно смещённая оценка, в ресемплах с повторами сильнее), поэтому
    точечное значение может лежать ниже нижней границы (`sp_pos` cross-fit 0.013 [0.01; 0.08]). В 10-бинной таблице
    есть бины из 1–6 кадров; MCE по таким бинам (до 0.85) не интерпретируется.
12. Кадры одного исследования коррелированы (166 кадров = 99 исследований, 329 = 78; 252 уникальных кадра из 499),
    эффективный объём выборки меньше номинального; все ДИ считаются по исследованиям, но диаграммы построены по кадрам.
13. Оценка — одно разбиение OOF; разброс по разбиениям для AUC показан в `docs/METRICS_REPORT.md` («Разброс по
    разбиениям»), для калибровки не оценивался. Platt в `calibration.pkl` обучен на всём OOF без cross-fit, поэтому его
    in-sample числа (ECE10 0.04–0.07) на новых данных не воспроизведутся — ориентироваться на строки cross-fit.
14. Ничего из этого не меняет поставку: калибровка `quality_prob` по-прежнему не внедряется
    (`calibration.apply_to_quality_prob: false`, обоснование в `docs/METRICS_REPORT.md`), `p_cal` остаётся в debug-CSV и
    API details, 9 колонок CSV прежние. Отчёт — инструкция по чтению чисел, а не изменение чисел.

## Воспроизведение

```
OMP_NUM_THREADS=1 python tools/calibration_report.py --bins     # таблицы в stdout, JSON и SVG в docs/calibration/
python tests/test_calibration_report.py                          # 7 проверок, около 3 с
```

Структура `docs/calibration/calibration.json`: `regions.<spine|hip>.variants.<final|raw_blend>`,
`criteria.<crit>.variants.<score|p_cal|p_cal_crossfit>` (каждый вариант: `n, n_pos, n_studies, n_pos_studies, brier,
brier_const, brier_skill, log_loss, ece_10, mce_10, ece_q5, mce_q5, slope, intercept, roc_auc, bins_equal_10,
bins_quantile_5, ci95`), `criteria.<crit>.platt_crossfit_folds`, `uncertain_zone.<crit>`, `inputs` (пороги, запасы,
параметры Platt), `method`, `svg_files`. Путей к кадрам и идентификаторов пациентов в JSON нет.

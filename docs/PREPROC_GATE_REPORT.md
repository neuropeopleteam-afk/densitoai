# К11. Инвариантная предобработка и выбор варианта по критерию

Дата: 2026-09-20. Версия: 2.2.0. Код: `src/preprocess.py`, `tools/preproc_gate.py`, `tools/build_exposure_reference.py`.
Решения: `models/preproc_gate_decisions_a.json`, `models/preproc_gate_decisions_b.json`. Конфиг: `config.yaml: preprocessing`.

## 1. Задача

`docs/ROBUSTNESS_REPORT.md` (замер 2026-09-20 на порогах К3, n = 81): к сдвигам формата система устойчива
полностью (пересохранение, удаление тегов, отсутствие UID, MONOCHROME1, 12 бит в 16-битном контейнере —
flip-rate 0.0 %), но при изменении экспозиции и шуме класс качества переворачивается у четверти кадров:
шум σ = 3 % — 28.4 %, гамма 0.7 — 25.9 %, гамма 1.4 — 39.5 %.

Причины из кода (`src/hip_features.py`, `src/geometry_features.py`):

1. **Шум.** Маска тела бралась жёстким порогом по сырому кадру (`img_u8 > 8`). Шум σ = 3 % — это ≈ 8 уровней
   из 255, поэтому воздух попадал в «тело», порог Otsu по телу смещался, порог кости `0.75·Otsu` уезжал.
2. **Экспозиция.** Перцентильное окно 1–99 % компенсирует только линейные сдвиги яркости. Степенное
   (гамма) остаётся, а признаки интенсивности и Otsu к нему не инвариантны.

## 2. Что сделано

`src/preprocess.py` — три варианта предобработки, общие для контура A (геометрия) и контура B (эмбеддинги):

| Вариант | Маска тела | Экспозиция |
|---|---|---|
| `baseline` | порог 8 по сырому кадру (как в 2.1.0) | как есть после окна 1–99 % |
| `mask` | порог 8 по сглаженному кадру (`GaussianBlur 5×5`) | как есть |
| `canonical` | порог 8 по сглаженному кадру | канонизация: один параметр γ к эталону обучения |

**Канонизация экспозиции.** По квантилям пикселей тела (10/25/50/75/90 %) оценивается один параметр γ,
приводящий кадр к эталонному распределению (`models/exposure_reference.json` — медиана квантилей по 499
кадрам обучения), и применяется `x → x^γ` через LUT. γ ограничена [0.5; 2.0] и округляется до сетки 0.02
(иначе микроскопическая разница входа — те же пиксели в 12 битах вместо 8 — давала другой LUT и лишний
разброс решений; без округления это добавляло 1/81 переворот на 16-битном контейнере).

Почему это снимает искажение точно, а не приблизительно: монотонное преобразование действует на квантили
так же, как на пиксели. Для чистого кадра с квантилями `q` оценка даёт γ₀ (`q^γ₀ = ref`); для того же кадра,
искажённого гаммой `g` (квантили `q^g`), оценка даёт γ₁ = γ₀/g, и после коррекции получается
`(x^g)^(γ₀/g) = x^γ₀` — ровно тот же кадр, что из чистого входа.

Эталон построен по обучающей выборке, поэтому на ней канонизация близка к тождеству:
γ медиана 1.000, |γ − 1| медиана 0.107, p95 0.338, диапазон [0.637; 1.536], в ограничитель не упёрся ни
один из 499 кадров. Диапазон обучающей выборки перекрывает тестовые искажения 0.7 и 1.4 — то есть порогового
правила «свой/чужой кадр» тут не хватило бы, канонизация нужна всегда.

Проверка обратной совместимости: вариант `baseline` воспроизводит признаки 2.1.0 **бит в бит** (93 числовые
колонки × 499 строк, максимум |Δ| = 0.0).

## 3. Почему вариант выбирается по критерию

Канонизация убирает из кадра одну степень свободы — общую экспозицию. Для **укладки** это шум. Для
**посторонних предметов** и **ROI** абсолютная плотность — это сигнал: «предмет ярче кости» и «сколько
пикселей выше порога кости» после канонизации частично стираются. Поэтому вариант выбирается по критерию,
и выбор делается внутри nested, а не глазами.

Протокол — тот же, что у К2 (`tools/nested_gate.py`), чтобы числа были сравнимы: внешний контур
GroupKFold(shuffle, seed 42+r) 5 фолдов × 10 повторов, группы — компоненты связности (study, pixel_hash)
на сырой предобработке (499 файлов, 252 уникальных кадра); внутренний контур GroupKFold 3 фолда, выбор
варианта по максимуму AUC стэка на inner-OOF, при равенстве — консервативно `baseline`; порог — правило
критерия из `config.yaml: thresholds_rule` (К3), считается на inner-OOF; на внешнем тесте — модели с
всего внешнего train, ранги относительно inner-OOF-референса, стэк 0.5/0.5.

Две стадии, чтобы решения по контурам не смешивались: **стадия a** — выбор варианта контура A (эмбеддинги
в обеих ветках одинаковые, как в 2.1.0); **стадия b** — вариант A зафиксирован решением стадии a в обеих
ветках, сравниваются только эмбеддинги.

| sp_axis | 40 / 0 / 10 | −0.003 | [−0.026; +0.004] | 0/10 | +0.002 | baseline |

Вариант `mask` для позвоночника даёт признаки **бит в бит** как `baseline` (маску тела использует только
сегментатор бедра `segment_bone_hip`, спинной `segment_bone` считает Otsu по всему сглаженному кадру),
для бедра — разница в пределах шума (−0.0003 / −0.0045). Отдельной ценности как самостоятельный вариант
`mask` не показал и в продакшене не используется: он входит в `canonical`.

| Критерий | Контур A | Контур B |
|---|---|---|
| sp_pos | canonical | `densito` на canonical |
| sp_axis | baseline | `imagenet` на baseline |

Формально правило приёмки К2 (прирост ≥ 0.03 в ≥ 7/10 повторов) не прошёл ни один критерий: выигрыш
sp_pos устойчив по знаку, но по величине меньше порога приёмки. Принято по правилу «выбор варианта внутри
nested + отсутствие потери macro-F1»: критерии, где nested выбрал `canonical` в большинстве фолдов
(sp_pos 44/49, hip_pos 30/50), переведены на него; остальные остались на `baseline` без изменений.

Бинарное «есть нарушение»: позвоночник ROC-AUC 0.764 → 0.758, F1 0.618 → 0.609, macro-F1 0.439 → **0.464**;

## 5. Результат на устойчивости (n = 81, тот же `tests/robustness_suite.py`)

| Искажение | flip 2.1.0 | flip 2.2.0 |
|---|---|---|
| identity (пересохранение) | 0.0 % | 0.0 % |
| теги удалены | 0.0 % | 0.0 % |
| нет UID | 0.0 % | 0.0 % |
| MONOCHROME1 | 0.0 % | 0.0 % |
| 16-битный контейнер (12 бит) | 0.0 % | 0.0 % |
| гауссов шум σ = 3 % | 28.4 % | **27.2 %** |
| ярче (гамма 0.7) | 25.9 % | **21.0 %** |
| темнее (гамма 1.4) | 39.5 % | **17.3 %** |
| resize ×0.8 | 17.3 % | 19.8 % |
| resize ×1.25 | 9.9 % | 8.6 % |
| обрезка 4 % | 16.0 % | 16.0 % |

Главный выигрыш — «темнее» (39.5 → 17.3 %) и «ярче» (25.9 → 21.0 %). Шум сдвинулся мало (28.4 → 27.2 %),
потому что канонизацию получили только два критерия укладки, а половину стэка этих критериев (и весь стэк
остальных) по-прежнему считает контур B на сыром кадре. Время обработки 0.038 → 0.041 с на снимок
(предел ТЗ — 3 мин на исследование).

**Замеренная альтернатива** (не принята). Если перевести и контур B критерия hip_pos на canonical
(одна строка `config.yaml`: `hip_pos: {geom: canonical, emb: canonical}` + `train_stacked.py` +
`train_final_models.py`), устойчивость заметно лучше: гамма 0.7 — 12.3 %, гамма 1.4 — 14.8 %,
шум — 24.7 %, resize ×0.8 — 16.0 %, время 0.07 с. Цена: hip_pos AUC 0.725 → 0.710 (всё ещё выше 2.1.0 —
0.704), F1 0.432 → 0.430. Nested стадии b этот вариант не принял (ΔAUC −0.003, ДИ [−0.038; +0.023]),
поэтому в продакшене он выключен; замер оставлен здесь, чтобы решение можно было пересмотреть, если
заказчику устойчивость важнее, чем 0.015 AUC на одном критерии.

## 6. Что осталось нерешённым

- **Шум.** Перевороты при σ = 3 % почти не уменьшились. Источник — контур B (эмбеддинги считаются по
  сырому кадру) и спинной `segment_bone` (Otsu по всему кадру). Денойзинг перед CNN потребует пересчёта
  эмбеддингов и полного nested-протокола заново — не делали.
- **Масштаб и обрезка.** 8.6–19.8 % переворотов; признаки в мм пересчитываются по PixelSpacing, но
  площадные признаки и фиксированный resize 320×192 перед CNN не инвариантны. Не трогали.
- **Зона «не уверен» (К3)** эти перевороты по-прежнему не закрывает: они сосредоточены у порога, но
  margin подобран под крышу отказов 5 %.
- Эксплуатационная оговорка остаётся: все снимки одного отделения приходят с одного аппарата GE Lunar
  с фиксированным экспортом, поэтому на реальном потоке гамма и шум не меняются; эти искажения — признак
  «чужого» аппарата, и их ловит OOD-gate (К9).

## 7. Воспроизведение

```bash
python tools/build_exposure_reference.py --write          # эталон экспозиции по обучающей выборке
python src/extract_all_features.py --variant baseline     # data/geometry_features.csv
python src/extract_all_features.py --variant mask         # data/geometry_features_mask.csv
python src/extract_all_features.py --variant canonical    # data/geometry_features_canonical.csv
python src/embeddings.py --source imagenet --variant baseline    # data/embeddings.npy
python src/embeddings.py --source imagenet --variant canonical   # data/embeddings_canonical.npy
python src/embeddings.py --source densito  --variant baseline    # data/embeddings_densito.npy
python src/embeddings.py --source densito  --variant canonical   # data/embeddings_densito_canonical.npy
python tools/make_pixel_hashes.py --variant baseline      # группы для nested
PREPROC_STAGE=a N_REPEATS=10 python tools/preproc_gate.py
PREPROC_STAGE=b N_REPEATS=10 PREPROC_FIXED_VARIANTS='{"sp_pos":"canonical","sp_axis":"baseline","sp_art":"baseline","hip_pos":"canonical","hip_roi":"baseline"}' python tools/preproc_gate.py
python src/train_stacked.py && python src/train_final_models.py && python src/eval_oof_metrics.py
python tests/robustness_suite.py --n 81
python tools/hash_weights.py --root . && bash tools/verify.sh --update-expected
```

Откат к поведению 2.1.0: `config.yaml: preprocessing.enabled: false`, затем `train_stacked.py`,
`train_final_models.py`, `tools/hash_weights.py --root .`, `bash tools/verify.sh --update-expected`.

# Nested-валидация вентильного стэкинга (К2) — полный отчёт

Скрипт: `work/B/nested_gate.py`; данные: `densito_rebuild/data/geometry_features.csv`, `embeddings.npy`, `embeddings_densito.npy` (sp_pos). Запуск 19.09.2026, 10 повторов, 148 с (OMP_NUM_THREADS=1). Лог: `results/nested_gate_log.txt`.

## Протокол

- Внешний контур: GroupKFold, 5 фолдов × 10 повторов, `shuffle=True, random_state=42+r`. Замечание: перестановка строк, как в `train_stacked.py`, разбиение GroupKFold не меняет (группы раскладываются по размеру) — 5 «повторов» там фактически одинаковы; здесь используется настоящий шаффл групп (sklearn 1.9.1).
- Группы: компоненты связности графа (study, pixel_hash), sha1 нормализованных пикселей (`inference.normalize_pixels`). Файлов 499, уникальных изображений 252, групп дубликатов 127, файлов в них 374; групп, объединяющих разные исследования, — 0, т.е. группа = исследование (99 групп для позвоночника, 79 для бедра). Размеры групп дубликатов: 2 файла — 71 группа, 3 — 20, 4 — 22, 5 — 11, 9 — 1, 10 — 2 (`results/pixel_hashes.csv`).
- Внутренний контур: GroupKFold 3 фолда на внешнем train; модели ровно как в `train_stacked.py` (geom: StandardScaler→LogReg C=1 balanced; emb: StandardScaler→PCA32→LogReg C=0.1 balanced; PCA только на train-части). Медианы для импутации — по внешнему train.
- Выбор w_geom ∈ {0, 0.25, 0.5, 0.75, 1} по AUC стэка на inner-OOF (ранги pct внутри inner-OOF); при равенстве — ближайший к 0.5. Порог — на inner-OOF стэке по правилу `train_stacked` (F1-опт при ≥15 позитивов в train, иначе prevalence).
- Внешний test: модели, обученные на всём внешнем train; ранги — относительно inner-OOF-референса (`inference.percentile_rank`); стэк = w·rank_geom + (1−w)·rank_emb; база — w=0.5 с порогом, подобранным тем же способом.
- Метрики: AUC и macro-F1 по каждому повтору (outer-OOF на всех строках); итог — outer-OOF скор, усреднённый по повторам (AUC), и голосование предсказаний по повторам (F1); ДИ — бутстрап по исследованиям (1000).
- Приёмка: прирост AUC ≥ 0.03 в ≥ 7 из 10 повторов И средняя macro-F1 вентиля не ниже базы.

## Часть 3: бэклог консилиума, идеи 12–15 (23.09.2026, база = боевая 2.3.2)

Харнесс `tools/backlog_gate.py` (nested repeated GroupKFold 5 внешних × 20 повторов × 3 внутренних,
seed 42+r / 1000·r+k как в `tools/nested_gate.py`, группы = компоненты (study, pixel_hash)); модели, источники
эмбеддингов, предобработка и правило порога — из `config.yaml` 2.3.2, региональный `quality_prob` считается как в
`src/inference.py`. База побайтно одна и та же во всех четырёх прогонах: sp_pos 0.762, sp_axis 0.860, sp_art 0.817,
hip_pos 0.733, hip_roi 0.880 (замороженные OOF 0.734 / 0.889 / 0.823 / 0.725 / 0.917 — расхождение из-за протокола,

для sp_axis, каноническая предобработка геометрии, пороги по `thresholds_rule`); sp_art и hip_roi совпадают с частью 1

## Часть 4: калиброванный гейт (идея 11, 23.09.2026)

Раздел описывает инструмент приёмки `tools/paired_gate.py`, его правило и калибровку на структуре наших данных.
Числа метрик по критериям не меняются; меняется только способ решать, «лучше ли кандидат базы».

### Зачем

Старое правило вложенного гейта (ΔAUC >= 0.03 не менее чем в 70 % внешних повторов при не худшей средней macro-F1)
не имеет заявленного уровня ошибки: повторы repeated GroupKFold делят одни и те же 166 (329) объектов и различаются только
разбиением, поэтому «доля повторов с приростом» измеряет устойчивость к разбиению, а не к выборке. Ниже показано, что на
паре моделей с одинаковым истинным AUC старое правило принимает кандидата в 1–23 % случаев в зависимости от критерия,
а парный t-test по повторам — в 15–39 %.

### Метод

Вход — per-repeat внешние OOF-скоры базы и кандидата на одних и тех же фолдах (`results/gate_input_<region>_<crit>.csv`,
пишется харнессом `tools/nested_gate.py` через `paired_gate.write_gate_input`; формат в докстринге `tools/paired_gate.py`).
Единица ресэмплинга — кластер: компонента связности (исследование, pixel_hash); в нашей выборке дубликаты пикселей не
пересекают границ исследований (0 хэшей на 2 и более исследования), поэтому кластер совпадает с исследованием
(99 кластеров для позвоночника, 78 для таза).

Статистики:

* ΔAUC_r и Δmacro-F1_r — парные по повторам r; точечная оценка ΔAUC = среднее по повторам.
* Кластерный бутстрап: ресэмпл кластеров с возвращением (по умолчанию 4000), ΔAUC пересчитывается на каждом повторе и
  усредняется; ДИ 90 % и 95 % перцентильные; одностороннее p_boot = доля бутстрап-ΔAUC <= 0. Для macro-F1 та же
  процедура над средним по повторам Δmacro-F1_r (пороги берутся из предсказаний харнесса, выбранных на inner-OOF).
* Перестановочный sign-flip тест по кластерам: внутри случайно выбранных кластеров роли «база/кандидат» меняются
  местами (одновременно во всех повторах), статистика — среднее ΔAUC; при обменности групп тест точный.
* Парный t-test по повторам приводится только для справки.

### Правило принятия

Кандидат принят, если одновременно (уровень alpha = 0.05, односторонне):

1. нижняя граница кластерного ДИ (1 − 2·alpha_adj) для ΔAUC больше 0 (эквивалентно p_boot < alpha_adj);
2. p sign-flip теста < alpha_adj;
3. точечная оценка ΔAUC >= minimal_effect = 0.02;
4. не хуже по macro-F1: 20-й процентиль кластерного бутстрапа среднего по повторам Δmacro-F1 >= −0.01;
5. поправка на партию гипотез: alpha_adj = alpha / m для одного кандидата в партии из m (первый шаг Холма), при нескольких
   кандидатах за один вызов — полная процедура Холма или Бенджамини–Хохберга по p = max(p_boot, p_perm)
   (`--n-hypotheses m --family holm|bh`).

### Почему t-test по повторам завышает уверенность

Стандартная ошибка t-теста равна sd(ΔAUC_r)/sqrt(R), где разброс между повторами отражает лишь изменчивость разбиений
(0.033–0.041 по критериям), и с ростом R стремится к нулю. Неопределённость же относительно генеральной совокупности
задана числом кластеров с позитивами (6–24) и в бутстрапе не уменьшается с R: для sp_pos под бинормальным нулём
бутстрап-SE равна 0.05–0.08 против 0.013 у t-теста при R = 10. В симуляции t-test принимает пару моделей с одинаковым
AUC в 15–39 % случаев, а при удвоении R ошибка не падает (sp_pos: 26–37 % при R = 10, 34–39 % при R = 20).

### Ограничения

* При n_pos ≈ 10 (sp_pos: 10 позитивов в 6 исследованиях) мощность любого правила низка. Реалистичный эффект +0.05
  ловится с вероятностью 0.14, +0.08 — 0.36; даже в оптимистичной модели «база + сигнал» мощность упирается в потолок
  около 0.77 из-за дискретности sign-flip теста на 6 информативных кластерах. Ни один эффект до +0.08 не ловится с
  вероятностью >= 0.8; для sp_pos гейт может только не пропускать ложное, но не подтверждать умеренное истинное улучшение.
  Старое правило на этом критерии выглядит «мощнее» (0.65 при +0.08) лишь потому, что принимает 11–23 % пустых кандидатов.
* Для sp_axis, sp_art, hip_pos, hip_roi эффект +0.03 в модели «база + сигнал» ловится с вероятностью 0.79–0.93 при R = 20,
  а в бинормальной модели порог мощности 0.8 достигается только при +0.08. Различие моделей само по себе показывает,
  что «истинный эффект +0.03» — не одно число: важна корреляция кандидата с базой.
* Увеличение числа повторов с 10 до 20 почти не добавляет мощности (кластеров не становится больше); полезнее увеличивать
  число исследований с позитивами.
* Условие по macro-F1 в симуляции почти не срабатывает (кандидат строится с тем же направлением эффекта по F1); его роль —
  страховка от кандидата, выигрывающего по AUC и проигрывающего по решениям на порогах.
* Бутстрап кластеров при 6 кластерах с позитивами перцентильный, а не BCa; его небольшая либеральность компенсируется
  sign-flip условием, но при m > 5 гипотез в партии alpha_adj становится меньше разрешающей способности перестановочного
  распределения на 6 кластерах (минимальное p около 1/64).

## Часть 5: кандидат H2 по sp_pos — синтетическая голова укладки (идея 24, 23.09.2026)

Решение владельца (вариант А, 23.09.2026): H2 выводится в боевой критерий `sp_pos`, версия 2.4.0.
Материалы эксперимента: `docs/experiments/gpu_sppos/REPORT.md`, `docs/experiments/gpu_sppos/outputs/`; таблица «было → стало» пакета вывода: `docs/experiments/sppos_promote_before_after.md`.

### Что такое H2

Признак контура A `synth_pos_logit` — логит головы, обученной на синтетических смещениях кадра без меток.
Голова (`models/head_densito_synth.pth`, 1.3 МБ: Dropout → Linear 1280×256 → GELU → Linear 256×4, признак — первый
выход) стоит поверх замороженного бэкбона `densito` и принимает канонический эмбеддинг кадра — тот же, что контур B
`sp_pos` уже считает (вариант предобработки `canonical`, источник `densito`, `src/embeddings.py`). Обучение головы
(`docs/experiments/gpu_sppos/gpu/sppos_synth_train.py --mode head`, версия синтеза v3, зерно 0): ко всем 166 кадрам позвоночника
применялись случайные окна (масштаб 0.65–1.0, сдвиг центра), метка — «окно смещено»; разметка ТЗ в обучении головы не
участвует. Признак подаётся третьим в геометрическую модель контура A `model_spine_sp_pos_geom.pkl`
(StandardScaler → LogReg) вместе с `center_offset_ratio` и `bone_width_ratio`; контур B, веса стэка 0.5/0.5, правило
порога prevalence и any-модель региона не меняются. Код: `src/sppos_head.py` (загрузка, детерминизм, путь без torch
для сверки), `src/inference.py` (`_add_embedding_features`), `config.yaml → features`, `src/train_stacked.py`
(`CRITERION_EXTRA_COLS`), `tools/add_sppos_head_feature.py` (колонка в `data/geometry_features_canonical.csv`).

Сверка воспроизводимости скора: sigmoid(логит) на CPU-эмбеддингах `data/embeddings_densito_canonical.npy` против
`docs/experiments/gpu_sppos/outputs/scores_synth_head_v3.csv` (`p_defect`, посчитан на GPU-эмбеддингах): max |Δp| 0.0022,
медиана 0.0003, 458/499 строк в допуске 1e-3, ранговая корреляция по позвоночнику 0.99996. Остаток — разница
GPU/CPU-эмбеддингов бэкбона (до 0.0039 по компоненте, `docs/experiments/gpu_sppos/REPORT.md`, п. 1), не головы; в обучении стека
и в продакшене используется CPU-логит, поэтому обучающий признак и признак инференса — одна и та же величина.

### Гипотезы

- (а) Порог критерия, попавший на уровень связанных рангов референса, переносится в середину между
  соседними уникальными уровнями (на референсе это строгий «>» вместо «>=»). На сохранённых OOF все пять
  порогов лежат ровно на уровне: флагов sp_pos 18 → 8, sp_axis 26 → 23, sp_art 51 → 47, hip_pos 83 → 78,
  hip_roi 19 → 15; macro-F1 по 5 критериям in-sample 0.517 → 0.573. Порог и эти числа выбраны на тех же
  данных, поэтому проверка — вложенная.
- (б) Одно нарушение на строку: при двух и более флагах остаётся тип с наибольшим запасом
  (score − thr) / (1 − thr); второй тип сохраняется, если его запас ≥ τ. τ ∈ {0 (выкл.), 0.05, 0.1, 0.2,
  0.3, 0.5, ∞} выбирается на inner-OOF отдельно для каждой области. OR флагов не меняется по построению;
  в расчёте проверено тождество бинарного класса и `quality_prob` во всех фолдах (assert в
  `decision_layer_eval.py`, тест `test_exclusive_keeps_or_identity`).

### Метод

5 внешних фолдов × 20 повторов × 3 внутренних, группы = исследование + pixel_hash; модели и пороги
критериев — как в `train_stacked.py`, но обучены только на внешнем train; порог (а) и τ (б) — только
по inner-OOF. Метрики на внешних фолдах, пул по повтору; кластерный бутстрап 2000 ресэмплов исследований,
ДИ 90 %. Строки вырожденных фолдов (порог не определён) исключаются из метрик повтора: в среднем
164.75 из 166 строк позвоночника и 317.55 из 329 строк бедра. Повтор на уникальных кадрах — один кадр на
pixel_hash: 99 строк позвоночника и 150 строк бедра с метками (249; из 252 уникальных кадров у трёх нет
меток бедра).

### Замечание о связках

Боевой порог sp_pos 0.8614457831325302 и hip_roi 0.9179331306990881 равны уровню OOF только при чтении CSV с
`float_precision='round_trip'`; парсер pandas по умолчанию даёт уровень на 1 ulp ниже, и число флагов на
OOF меняется (sp_pos 18 → 8, hip_roi 19 → 15). Решение `score >= thr` на этих блоках зависит от последнего
бита; инструменты, читающие OOF из CSV, должны использовать `round_trip`.

### Признак

в сервисе `c = 0.7`, колонки `metal_metal_band70_area_log` и `metal_metal_band70_max_gap` (`config.yaml -> geometry_cols.sp_art`).

### Решение

Признак `sp_art` в зоне измерения включён в 2.5.0 **решением владельца** — так же, как голова укладки H2 (`sp_pos`) в 2.4.0 (часть 5).

- Правило проекта (ΔAUC ≥ 0.03 в ≥ 70 % повторов без потери macro-F1) пройдено: 19 из 20 повторов в ветке с выбором отсечки,
  на фиксированной отсечке 70 % — 20 из 20; Δmacro-F1 +0.074, ни в одном повторе macro-F1 не упала.
- Калиброванный гейт не пройден: ДИ95 [−0.029; +0.176], p_boot 0.072, sign-flip 0.092. В отличие от H2 (6 положительных
  исследований) здесь 17 положительных исследований, и по калибровке проекта мощность гейта для `sp_art` при эффекте +0.03 равна 0.87.
  Поэтому отказ гейта — не нехватка мощности, а признак неоднородности прироста по исследованиям (SE 0.051 при среднем +0.066).
- На 40 кадрах слепой проверки врачей (OOF) эффекта нет: совпадение с разметкой 27 → 28 из 40; найдено с верной причиной 13 из 20
  без изменений (добавленная находка — по неверной причине); ложных тревог 6 из 20 без изменений (одна снята, одна добавлена);
  совпадение с большинством врачей 31 → 30 из 40 (`docs/REVIEW_DOCTORS.md`, дополнение 2.5.0).
- Механизм: прежний признак в основном считал предметами крылья подвздошных костей внизу кадра; новый их не учитывает. В верхнюю
  полосу при этом попадают и плотные участки анатомии у верхних углов кадра (показы 5 и 32 слепой проверки).

Что изменилось в замороженных OOF-числах 2.4.0 → 2.5.0 (`models/metrics_summary.json`, `docs/METRICS_REPORT.md`): `sp_art` контур A
0.560 → 0.804, стек 0.823 → 0.899, порог 0.602 → 0.624, чувствительность / специфичность 0.657 / 0.786 → 0.800 / 0.840,
F1 0.535 [0.24; 0.74] → 0.667 [0.39; 0.83]; бинарная задача позвоночника F1 0.662 → 0.737, ROC-AUC 0.813 → 0.846; macro-F1
позвоночника 0.547 → 0.590. Бедро не меняется. Nested-поля `sp_art` в `metrics_summary.json`: база 0.8175, в сервисе 0.8836,
повторов с приростом 19 из 20.

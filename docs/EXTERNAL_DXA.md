# Проверка переноса на внешние DXA-наборы (пункт В)

Дата: 24.09.2026. Образ `densitoai:2.4.0` (`7bc972168473`), `config_hash` 1f12392d7373, запуск
`docker run --network none --cpus 2 --memory 3g … batch`. **Без обучения, без смены порогов и признаков.**
Цель — понять, как сервис ведёт себя на снимках чужих аппаратов и форматов, а не измерить качество:
разметки укладки в этих наборах нет, поэтому метрик ROC-AUC/F1 здесь нет и быть не может.

## Данные

| Набор | Источник | Что это | Взято | Ожидаемая область |
|---|---|---|---|---|
| A2 DEXA-Osteo | Kaggle `mahavisnuks/dexa-osteo` | DXA поясничного отдела L1–L4 с контурами ROI сканера, PNG | 344 уникальных из 351 (дубликаты по md5 убраны) | позвоночник |
| A1 Arak | Kaggle `tommyngx/arak-bone-densitometry-center` | DXA бедра, вырез из отчёта с ROI сканера, PNG | 500 случайных из 4 019 уникальных (зерно 20260924) | бедро |
| B1 Chinese Osteoporosis, Hip | Kaggle `tommyngx/chinese-osteoporosis-dxa` | рентген-ROI бедра (не DXA), PNG | 60 (всё, что скачано) | бедро |

Лицензии и описание — `docs/DATASETS_DEEP_SEARCH.md`. Файлы лежат вне репозитория:
`/opt/neuropeople/external_datasets/`, DICOM-обёртки и выходы — `/opt/neuropeople/densito_private/external/`.
Имена файлов заменены хэшем (в B1 в именах были имена пациентов).

Обёртка PNG → DICOM (`densito_private/external/ext_dxa.py`): 8 бит, MONOCHROME2, Secondary Capture,
`Modality = OT`, `Manufacturer = external PNG`, `PixelSpacing` не задан (как и в данных заказчика; сервис
берёт значение по умолчанию для аппарата 1,05 × 0,6 мм — это допущение, у чужих аппаратов шаг другой).
Каждый PNG — отдельное исследование.

## Что это значит

1. **Сервис устойчив технически**: 904 чужих файла, 0 падений, время на файл того же порядка, что и на
   боевом сервере.
2. **Сервис не распознаёт «чужой домен» и уверенно ошибается.** На всех трёх наборах доля «нарушений»
   70–92 % при высокой quality_prob (медиана 0,93–1,00), а отказ по области не срабатывает ни разу. Причины
   видны по типам нарушений: в A2 контуры ROI, впечатанные сканером в картинку, детектор принимает за
   посторонние предметы (304 из 344); в A1 вырез отчёта другого формата — 41 % снимков бедра определены
   как позвоночник (по размеру кадра), дальше геометрия не сходится.
3. Это подтверждает ограничение, которое уже записано в `models/MODEL_CARD.md` («один прибор … переносимость на другие приборы не проверена») и в `intended_use` сервиса: область
   применения — GE Lunar Prodigy; вне её результат не определён. Теперь это ограничение показано на данных.

## Что сделано по итогам (24.09.2026, решение владельца)

Входной фильтр аппарата в `src/region_support.py` (слой API и веба): если `Manufacturer` заполнен и явно не
GE/Lunar — строка получает `region_supported = False` с причиной «аппарат или формат вне области применения»
(те же 9 колонок, `processing_status` — как для неподдерживаемой области). На 499 файлах заказчика
(все 499 — CR, GE Healthcare, проверено по тегам) фильтр не срабатывает ни разу; на внешних наборах (Manufacturer = «external PNG») — 100 % отказов вместо
ложных «нарушений». Порог и модели не меняются; пакетный путь (CSV для организаторов) фильтр не вызывает.
Оговорка: у реальных снимков другого аппарата с пустым или обезличенным `Manufacturer` фильтр не сработает — сомнение
трактуется в пользу обработки, как и в остальных правилах модуля.

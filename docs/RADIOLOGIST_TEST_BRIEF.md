# Техническое задание врачу-рентгенологу: экспертная оценка сервиса DensitoAI

Версия сервиса 2.1.0 · время на работу — 2–3 часа · результат — письменное заключение по форме в §6.

## 1. Цель

Получить независимое клиническое заключение: правильно ли и «грамотно» ли сервис оценивает
качество DXA-снимков поясничного отдела позвоночника и проксимального отдела бедра, можно ли
доверять его сигналам как «второму читателю» и что нужно изменить, чтобы врач захотел им
пользоваться. Нужна критика, а не одобрение: каждый найденный дефект повышает шансы команды
на конкурсе, каждая скрытая проблема — понижает.

## 2. Что оценивается

Сервис по DICOM-снимку выдаёт: область (позвоночник / бедро), `quality_class` (1 — есть нарушение,
0 — снимок качественный), список нарушений и вероятность нарушения `quality_prob` (0…1).
Перечень нарушений закрытый (по ТЗ ДЗМ):

| Область | Нарушение | Что сервис измеряет (упрощённо) |
|---|---|---|
| Позвоночник | Некорректная укладка | смещение позвоночника от центра кадра, ширина кости в кадре |
| Позвоночник | Не выравнена ось позвоночника | угол оси позвоночника к вертикали (°) |
| Позвоночник | Присутствуют посторонние предметы | плотные инородные объекты (мм², контраст) |
| Бедро | Некорректная укладка | угол диафиза бедренной кости, поворот |
| Бедро | Некорректная область интереса | расстояние ROI до края кадра (мм, норма ≥ 20), доля кости в ROI |

Сервис не ставит диагноз, не оценивает МПК/T-score и не изменяет исходные файлы.

## 3. Что вам предоставляется

- Доступ к веб-интерфейсу: `https://neuropeople.pro` (логин/пароль выдаёт команда) — загрузка
  снимков, результат в таблице, визуализация с осью/контуром/ROI и панелью «скор / порог».
- Либо офлайн: Docker-образ и команда `./build_and_run.sh run <папка> ./outputs`
  (см. `docs/EXPERT_TESTING_GUIDE.md`); результат — `outputs/results.xlsx`, визуализации —
  флаг `--visualize-dir`.
- Набор снимков для проверки: 30–50 DICOM (желательно ваших, не из обучающего набора команды),
  включающих для каждой области и «норму», и каждый тип нарушения (по возможности ≥ 3 примера
  на тип). Если своих снимков нет — команда предоставит контрольную подвыборку.

## 4. Порядок работы

1. **Слепая разметка.** До запуска сервиса зафиксируйте своё заключение по каждому снимку:
   область, есть ли нарушение, какие именно (по перечню §2). Это эталон.
2. **Прогон.** Загрузите снимки в сервис (или запустите пакетную обработку). Для каждого
   снимка сравните вердикт сервиса со своим. Отметьте: совпадение / пропуск / ложное
   срабатывание / неверный тип нарушения / неверная область.
3. **Разбор расхождений.** Для каждого расхождения откройте визуализацию и посмотрите, что
   именно система «увидела» (линия оси, контур кости, границы ROI, отмеченные предметы,
   измерения в панели). Ответьте на вопрос: ошибка измерения (система не нашла кость/ось) или
   ошибка порога (измерила верно, но решила иначе, чем вы)?
4. **Проверка клинической логики.** Оцените пороги и формулировки: разумен ли порог наклона
   оси, площади инородного объекта, расстояния ROI до края; что бы вы изменили.
5. **Удобство.** Пройдите путь «загрузил → понял результат → что делать дальше» и запишите,
   что мешает.

## 5. На что обратить особое внимание

- Мультинарушения: если на снимке два нарушения, находит ли система оба.
- Грань «норма / лёгкое отклонение»: как система ведёт себя на пограничных снимках
  (по `quality_prob` около 0.4–0.6).
- Посторонние предметы: различает ли металл (протез, пуговица, молния) и плотные
  анатомические/артефактные структуры (кальцинаты, аорта, остеофиты, кишечное содержимое).
- Укладка бедра: реагирует ли на недостаточную внутреннюю ротацию (виден малый вертел),
  абдукцию/аддукцию, наклон таза.
- ROI бедра: отражает ли предложение «исправленного ROI» реальную практику оператора.
- Снимки других аппаратов или с нестандартным разрешением, если есть: корректно ли
  определяется область, помечается ли снимок как нестандартный.
- Формулировки в интерфейсе и отчёте: понятны ли врачу, не вводят ли в заблуждение.

## 6. Форма заключения (просим заполнить)

**А. Сводная таблица по снимкам** (можно xlsx): `файл | область (врач) | область (сервис) |
нарушения (врач) | нарушения (сервис) | quality_prob | вердикт: совпало/пропуск/ложное/тип/область | комментарий`.

**Б. Оценка по шкале 1–5** с одной фразой обоснования:

| № | Критерий | Оценка | Комментарий |
|---|---|---|---|
| 1 | Правильность определения области | | |
| 2 | Выявление «есть нарушение / нет» — согласие с вашим мнением | | |
| 3 | Правильность типа нарушения | | |
| 4 | Клиническая разумность порогов и измеряемых величин | | |
| 5 | Полезность визуализации для понимания решения | | |
| 6 | Понятность интерфейса и отчёта для врача | | |
| 7 | Готовность использовать как «второго читателя» в отделении | | |

**В. Три самых опасных ошибки** сервиса из увиденных (что и почему опасно для практики).

**Г. Три изменения**, которые больше всего повысили бы доверие врача.

**Д. Итоговый вывод** (3–5 предложений): пригоден ли сервис для пилота в отделении лучевой
диагностики при указанных ограничениях; при каких условиях.

Ваше заключение (с ФИО, должностью, стажем работы с DXA) будет включено в материалы команды с
явным указанием, что оно является независимой экспертной оценкой. Замечания, полученные до
финальной сдачи, команда постарается учесть и сообщит, что именно исправлено.

Контакт команды: лидер команды DensitoAI (контакт указывается при передаче ТЗ).

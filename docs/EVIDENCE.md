# Доказательная база DensitoAI v2.1.0

Один документ о том, откуда данные, как считались числа и что не подтвердилось. Каждое число — из файла проекта,
источник указан в скобках. Все метрики — out-of-fold (OOF); ничего не измерено на закрытом тесте организаторов.

## 1. Происхождение данных

- Обучающий набор организаторов: **499 DICOM-файлов, 100 исследований**, разметка — xlsx организаторов
  (`HANDOVER.md` §9; `data/labels_full.csv`, `data/labels_for_embeddings.csv`). Ключ соединения — папка исследования.
- Прибор один — **GE Lunar Prodigy**, все снимки сделаны в Москве на одних аппаратах (слова владельца, `HANDOVER.md` §9;
  QA_COMPLIANCE_MATRIX №1: pixel spacing Y = 1.05 мм, X = 0.6 мм, тегов в DICOM нет). Ширины кадра: 300 px позвоночник,
  280/248 px бедро (`config.yaml → regions.standard_cols`).
- Уникальных кадров по md5 пикселей — **252 из 499**; остальные 247 — побайтовые дубликаты внутри исследований, ни один
  хэш не встречается в двух исследованиях (`docs/IMPROVEMENT_ANALYSIS.md` §2). Поэтому группировка по исследованию
  исключает утечку дубликатов между обучением и валидацией.
- Разметка: один разметчик; столбец «Итог» организаторы назвали ошибочным — истина берётся из отдельных критериев,
  метка «есть нарушение» = OR критериев (`docs/qa/QA_COMPLIANCE_MATRIX.md` №9; `src/build_dataset.py`).
- Число валидных снимков и позитивов по критериям (`models/metrics_summary.json`): позвоночник n = 166 —
  sp_pos 10, sp_axis 17, sp_art 35; бедро n = 329 — hip_pos 79, hip_roi 16 (правое 7, левое 9). Бедро: 333 кадра в
  `data/labels_hip_canonical.csv`, 4 без применимой разметки исключены (`docs/IMPROVEMENT_ANALYSIS.md` §2).
- Конфиденциальность: DICOM организаторов в публичный репозиторий и эталонные пакеты не входят (`work/CONTEXT.md`,
  `HANDOVER.md`); карточка модели и схема не содержат данных пациентов.

## 3. Протокол валидации

- Обучение и OOF-оценка: `src/train_stacked.py` — repeated GroupKFold по исследованию (`README.md` §структура:
  «5×5 GroupKFold»); снимки одного исследования никогда не оказываются одновременно в обучении и валидации
  (`docs/METRICS_REPORT.md`).
- Доверительные интервалы: study-level percentile bootstrap, 95 %, 2000 повторов (`docs/METRICS_REPORT.md`;
  `src/eval_oof_metrics.py`).
- Пороги — только по OOF: `threshold_method` в `models/metrics_summary.json` (`prevalence` для sp_pos,
  `f1_optimal_oof` для остальных, общая hip-модель для сторон). Те же пороги использует инференс
  (`config.yaml → thresholds: null` → metrics_summary).
- Стекинг: ранговое усреднение перцентилей geom/emb 0.5/0.5 относительно OOF-распределения
  (`config.yaml → stacking`; `models/oof_stacked_*.csv`).
- Что **не** сделано: вложенная (nested) валидация выбора порога, веса стекинга и бэкбона — внешний фолд сейчас участвует
  в подборе порога. Это признанное ограничение (`docs/IMPROVEMENT_ANALYSIS.md` §3 «§8.1»; `PLAN.md` К2/К4); в
  `models/MODEL_CARD.md` — строка «nested: не рассчитано» до появления `nested_auc_mean` в `metrics_summary.json`.

Итоговые OOF-метрики (`models/metrics_summary.json`, `docs/METRICS_REPORT.md`):

| Критерий | n / n_pos | AUC geom | AUC emb | AUC стек | Порог | F1 [95 % ДИ] |
|---|---|---|---|---|---|---|
| sp_pos | 166 / 10 | 0.611 | 0.797 (densito) | 0.715 | 0.791 | 0.400 [0.00; 0.72] |
| sp_axis | 166 / 17 | 0.839 | 0.491 (imagenet) | 0.738 | 0.756 | 0.381 [0.10; 0.60] |
| sp_art | 166 / 35 | 0.560 | 0.897 (imagenet) | 0.823 | 0.602 | 0.535 [0.23; 0.73] |
| hip_pos | 329 / 79 | 0.694 | 0.635 (imagenet) | 0.704 | 0.643 | 0.420 [0.23; 0.59] |
| hip_roi | 329 / 16 | 0.902 | 0.877 (imagenet) | 0.917 | 0.918 | 0.514 [0.00; 0.89] |

Бинарная задача «есть нарушение» по итоговой `quality_prob`: ROC-AUC 0.764 [0.63; 0.88] позвоночник (n_pos 60),
0.732 [0.58; 0.86] бедро (n_pos 92); macro-F1 по типам 0.439 [0.25; 0.60] и 0.500 [0.21; 0.67] — при nested-выбранных правилах порога (К3, 19.09); при прежних F1-оптимальных порогах было 0.783 / 0.773 и 0.460 / 0.574 (оптимистично: порог подбирался на тех же OOF)
(`docs/METRICS_REPORT.md`, пересчитан 19.09 `python src/eval_oof_metrics.py` после внедрения бэкбона densito для sp_pos;
до пересчёта в отчёте стояли 0.775 / 0.662 / 0.453 для позвоночника, sp_pos 0.596 — устаревший OOF-файл).

## 5. Известные ограничения

- **Мало позитивов**: sp_pos 10 файлов / 6 исследований, sp_axis 17 / 10, ROI бедра 7 (правое) + 9 (левое) = 16 файлов
  на 6 исследованиях (`models/metrics_summary.json`; число исследований — `docs/IMPROVEMENT_ANALYSIS.md` §2);
  ДИ F1 для sp_pos [0.00; 0.72], для rh_roi/lh_roi [0.00; 1.00] (`models/metrics_summary.json`, пометка
  «ненадёжно: <10 позитивов»).
- **Один разметчик**, межэкспертного согласия нет; двойная разметка запланирована, не выполнена
  (`docs/IMPROVEMENT_ANALYSIS.md` §3).
- **Чувствительность к яркостной кривой и шуму** (`docs/ROBUSTNESS_REPORT.md`, 81 снимок): доля смены класса — гауссов
  шум σ = 3 % 22.2 % (18/81), гамма 0.7 24.7 % (20/81), гамма 1.4 28.4 % (23/81), resize ×0.8/×1.25 13.6 %/14.8 %,
  обрезка 4 % 8.6 %; формат-инварианты (пересохранение, удалённые теги, нет UID, MONOCHROME1, 16 бит) — 0 %.
  У 57–76 % перевернувшихся запас |score − порог| < 0.15. Область (spine/hip) не менялась ни в одном сценарии.
- **`quality_prob` не калибрована**: ранговый скор, согласованный с классом; Brier/ECE не считались
  (`config.yaml → stacking`; `docs/IMPROVEMENT_ANALYSIS.md` §3 «§8.4»).
- **Один прибор, одна организация**: на других денситометрах пороги геометрии могут требовать перекалибровки
  (`README.md` §14); OOD-детектор чужого аппарата не реализован (`PLAN.md` К9 ☐).
- **Локализация структур не валидирована** (нет Dice/IoU); оверлей показывает измеренную геометрию, а не проверенную
  сегментацию (`docs/IMPROVEMENT_ANALYSIS.md` §3 «§8.3»).
- Скорость: p50 0.04 с, p95 0.07 с на снимок без бонусов (`docs/ROBUSTNESS_REPORT.md`, identity); второй бэкбон для
  позвоночника ≈ +0.3 с/файл (`docs/GPU_EXPERIMENT.md`).

## 6. Угрозы валидности и как код их избегает

| Угроза (шорткат) | Почему опасна | Как избегаем в коде | Что не закрыто |
|---|---|---|---|
| Имя файла (`_ПОП/_ППОБ/_ЛПОБ`) как признак региона | В закрытом тесте суффиксов не будет (QA №7) | `src/inference.py: classify_region` — теги DICOM → ширина кадра → `models/model_region_emb.pkl`; подсказка имени применяется только при нестандартной ширине; регион записывается в `results_debug.csv: region_src`. `docs/ROBUSTNESS_REPORT.md`: без UID/тегов — 0 % переворотов | — |
| Белые линии разметки денситометра как конфаундер метки | Линии наносит аппарат/лаборант, они могут коррелировать с меткой качества | Специальной обработки в коде нет; модель контура A работает по геометрии сегментированной кости (Otsu по пикселям тела > 8, `docs/qa/QA_COMPLIANCE_MATRIX.md` №12), контур B — по всему кадру | Аудит «линии × метка» (`PLAN.md` К8) не проведён; ассоциация не измерена — заявлять устойчивость нельзя |
| Чёрные маски по краям бедренных снимков | Постобработка лаборанта, не признак (QA №12) | Сегментация Otsu по пикселям тела устойчива к маскам (QA_COMPLIANCE_MATRIX №12) | Маскирование чёрных краёв с проверкой OOF (`SYNTHESIS_ROUND2` п. 7) не выполнено |
| Утечка дубликатов между фолдами | 247 побайтовых дубликатов | GroupKFold по исследованию; дубликаты не пересекают исследования (`docs/IMPROVEMENT_ANALYSIS.md`) | — |
| Подбор порога на тех же OOF | Оптимистичная оценка F1 | Пороги подобраны по OOF, но без внешнего nested-контура | nested не рассчитан (см. §3) |
| Изменение оригинала / потеря ссылки на снимок в отчёте | Дефекты Г5/Г1 по методологии НПКЦ ДиТ (`docs/DZM_CONFORMANCE.md` §3) | SR исследования содержит SHA-256 файла и массива пикселей оригинала и ссылки на исходные SOPInstanceUID (`src/inference.py: _origin_hashes`; `src/dicom_sr.py: build_study_sr`); исходные файлы не перезаписываются | внешний `dciodvfy` в песочнике не запускался |
| Сопутствующая патология (сколиоз, эндопротез) как «нарушение укладки» | Организаторы: не нарушение (QA №10) | Ось оценивается относительно вертикали кадра «как есть» (QA №10–11) | правило «эндопротез» (`PLAN.md` К9) не реализовано |

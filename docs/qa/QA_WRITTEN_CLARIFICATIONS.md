**Вопрос 1.** В DICOM нет PixelSpacing и других тегов геометрической калибровки. Как считать критерии в сантиметрах - 3 см над большим вертелом, 2 см от бокового края? Будет ли масштаб добавлен, известен ли физический размер пикселя для этих выгрузок, или допустимо считать в долях изображения?

**Ответ:** Размеры пикселей у данного сканера 1,05 по оси Y и 0,6мм по оси X. В наборах данных будет единый вариант аппарата.

**Вопрос 6.** Какой закрытый список значений у violation\_type: коды или текст, на каком языке, чем разделять несколько нарушений, что писать при их отсутствии? Macro-F1 будет считаться по этому списку?

**Ответ:** Список значений для поясничного отдела позвоночника: [«Некорректная укладка»; «Не выравнена ось позвоночника»; «Присутствуют посторонние предметы»]

Список значений для проксимального отдела бедра: [«Некорректная укладка»; «Некорректная область интереса»]

При нескольких нарушениях перечислить через «;». При отсутствии оставить поле пустым.

**Вопрос 8.** quality\_class в выходной таблице - целое 0 или 1, по такой колонке ROC-AUC вырождается. Можно ли добавить колонку с вероятностью нарушения? Не помешают ли дополнительные колонки автоматической проверке?

**Ответ:** Можно добавить колонку с вероятностью нарушений. Название колонки «quality\_prob». Вероятность передается в диапазоне [0;1].

**Вопрос 15.** Какие значения писать в anatomical\_region: текстом «поясничный отдел, левое бедро, правое бедро» или кодами, как в именах файлов тестового набора? Будут ли такие суффиксы в именах файлов закрытого теста?

**Ответ:** Список значений для anatomical\_region: [«Поясничный отдел позвоночника»; «Проксимальный отдел бедра»]. Сторона (лево/право) не имеет значения. Суффиксов в именах файлов не будет.

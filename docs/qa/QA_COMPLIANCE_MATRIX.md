| 1 | Pixel spacing аппарата Lunar Prodigy Advanced: **Y = 1,05 мм, X = 0,6 мм** (тегов в DICOM нет; аппарат единый для всей Москвы) | Константы `PIXEL_SPACING_Y_MM = 1.05`, `PIXEL_SPACING_X_MM = 0.6` в `hip_features.py` / `geometry_features.py`; все мм-признаки (край кадра, длина скана, ширина диафиза) считаются через них | ✅ unit-тесты; отчёты в мм в оверлеях |

| 3 | `violation_type` — **текст, через `;`**, порядок не важен; пусто при отсутствии нарушений и тогда `quality_class = 0` | `violation_separator: ";"`, названия из `config.yaml → violations` строго по присланному словарю | ✅ `validate_output_csv` → `format_check: OK` |
| 4 | Типов нарушений **5**: 3 для позвоночника, 2 для бедра (позиционирование и ротация бедра объединены) | Критерии `sp_pos, sp_axis, sp_art, hip_pos, hip_roi` | ✅ |
| 5 | Столбец вероятности **`quality_prob`** приветствуется — по нему посчитают ROC-AUC; основной столбец 0/1 | Столбец есть; с v2.1.0 `quality_prob` согласован с классом (class=1 ⇔ prob ≥ 0,5), OOF ROC-AUC вырос: spine 0,735→0,771, hip 0,704→0,777 | ✅ |

## Разметка и обучение

| # | Разъяснение | Что делаем | Проверка |
|---|---|---|---|
| 9 | Колонка **«Итог» содержит ошибки**; истина — отдельные критерии (эксперты в них единодушны). Хоть одно нарушение → изображение с нарушением | `build_dataset.py` читает только колонки критериев, метка «any» = OR критериев | ✅ код |
| 10 | Сопутствующая патология (сколиоз, эндопротез, перелом, люмбализация) — **не нарушение укладки**; ось при сколиозе оцениваем «как есть» относительно вертикали кадра | Угол оси = линейная аппроксимация центров тел позвонков к вертикали кадра (оси сканирования); отдельных «диагнозов» не ставим | ✅ recall по оси 10/10 на трейне; FP разбираются в METRICS_REPORT |
| 11 | Угол оси — от **оси тел позвонков** (не отростков), от верхнего к нижнему видимому позвонку, относительно вертикали кадра = оси сканирования | Именно так: центральная линия по маске тел позвонков, угол к оси Y | ✅ |
| 12 | **Чёрные прямоугольные маски** по краям бедренных снимков — постобработка лаборанта, не признак. «Если модель на них смотрит — она ошибается» | Сегментация Otsu по пикселям тела (>8) устойчива к маскам. В трейне 15 файлов / 7 исследований с масками (все — норма): ложных срабатываний 1/7 (14 %) против 10/51 (19,6 %) по всем нормальным бёдрам → маски не ухудшают качество | ✅ проверено отдельно |
| 13 | Метрики закрытого теста считаются **последовательно**: сначала бинарно «есть/нет нарушение», затем macro-F1 по типам | Отчёт метрик построен так же (`METRICS_REPORT.md`: any-violation → по критериям) | 📝 |
| 14 | Внешние данные и предобученные модели разрешены; всё **локально**, без внешних API/LLM | EfficientNet-B0 (ImageNet) как замороженный экстрактор эмбеддингов, веса в образе; сеть при инференсе не нужна | ✅ контейнер без сети |
| 15 | Тестовое железо — как в ТЗ; аренда кластеров не поможет | CPU-инференс ~0,4 с/файл, 499 файлов за ~200 с без GPU | ✅ |

## Бонусы, которые организаторы назвали «плюсом»

| # | Пожелание | Реализация |
|---|---|---|
| 16 | Локализация структур / подсветка зон на изображении или дополнительной серии — «большой плюс» | ➕ Оверлей PNG с геометрией (ось, контур кости, линии критериев) + **DICOM SR** (Secondary Capture) на каждый снимок с нарушением, zip дополнительной серии в батче |
| 17 | Корректность области интереса = **полная визуализация зоны сканирования** (поле скана), а не белая разметка аппарата | ➕ `auto_roi.py`: измерение отступов в мм и **рекомендация коррекции ROI** («+N мм») на PNG, когда критерий нарушен |
| 18 | Оценка белой разметки денситометра — «вообще шикарно», но не требуется | 📝 не реализовано намеренно: разметка есть не на всех снимках, эталона нет; описано в «Ограничения» |
| 19 | Защита от посторонних (не спина / не бедро) изображений — на тесте их не будет | ➕ Не-DICOM и повреждённые файлы → строка `processing_status = Failure`, `quality_prob = 0.5`, без исключений; валидация размеров кадра |
| 20 | Устойчивость к другим аппаратам — бонус | 📝 Геометрический контур зависит только от пиксель-спейсинга (параметр конфига); описано в «Ограничения» |
| 21 | Инструкция и механизм проверки для экспертов — прямо влияет на оценку | ➕ README с одной командой запуска, Swagger `/docs`, веб-демо, `EXPERT_TESTING_GUIDE.md` |

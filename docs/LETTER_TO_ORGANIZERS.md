## Как проверить за 3 команды

```bash
git clone https://github.com/neuropeopleteam-afk/densitoai.git && cd densitoai
./build_and_run.sh build                      # docker build + самопроверка
./build_and_run.sh run /path/to/test_dicoms ./outputs   # → outputs/results.csv и results.xlsx
```

Формат `results.csv` — строго по п.2.5 ТЗ и вашим письменным разъяснениям: колонки
`path_to_study, study_uid, image_uid, anatomical_region, quality_class, violation_type,
quality_prob, processing_status, time_of_processing`; одна строка на каждый файл (дубли не
схлопываются); `anatomical_region` ∈ {«Поясничный отдел позвоночника», «Проксимальный отдел
бедра»}; `violation_type` — значения из присланного словаря через «;», пусто при отсутствии
нарушений; `quality_prob` ∈ [0; 1], согласована с `quality_class` (класс 1 ⇔ prob ≥ 0,5).
Файлы, которые не удалось прочитать, получают `processing_status = Failure` без прерывания
пакета.

## Что учтено из Q&A-сессии и письменных разъяснений

- Размер пикселя Lunar Prodigy Advance 1,05 × 0,6 мм — все критерии в мм считаются через него.
- Колонка «Итог» разметки не использовалась; истина — отдельные критерии, «есть нарушение» =
  OR критериев.
- 5 типов нарушений (3 + 2), словари `violation_type` и `anatomical_region` — дословно.
- Регион определяется по содержимому снимка (теги DICOM → ширина кадра → контентная модель),
  имена файлов для решения не нужны.
- Угол оси — от оси тел позвонков к вертикали кадра; сопутствующая патология не считается
  нарушением; чёрные маски на бёдрах не являются признаком.
- Метрики в `docs/METRICS_REPORT.md` посчитаны в вашем порядке: бинарно по областям, затем
  macro-F1 по типам, всё — out-of-fold с группировкой по исследованию и 95 % ДИ.

Полный перечень — `docs/qa/QA_COMPLIANCE_MATRIX.md`.

## Бонусы (п.2.6), реализованы и включены в API

Серия визуализации по каждому снимку (измерения и оценки моделей по критериям) — как PNG и как
DICOM Secondary Capture рядом с исходной серией (производное изображение со ссылкой на исходный
снимок, детерминированными UID и предупреждением в пикселях), один DICOM Structured Report
(Comprehensive SR) на исследование с вердиктом и измерениями, сегментация структур (PNG-маска и DICOM SEG),
zip-архив дополнительных серий `additional_series.zip` (ТЗ п. 2.7), диагностика области интереса
бедра с дефицитом скана в мм, команда лаборанту с измеренным основанием, приём снимков по DICOM
(Storage SCP), веб-интерфейс с журналом исследований и проверкой вслепую. Подробно — `README.md`,
`CHANGELOG.md`.
